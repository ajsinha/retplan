# RetPlan — Data Model

Two kinds of data: the **plan**, a tree of dataclasses serialised as one JSON
document per scenario; and the **portfolio data**, relational tables shared by the
portfolio, price and securities features. Both live in one database whose schema
is `schema/sqlite.sql` / `schema/postgres.sql`.

---

## 1. Database

### 1.1 Conventions

- **DR-1.** Timestamps are ISO-8601 UTC text (`2026-09-29T14:03:11+00:00`); dates
  are ISO-8601 text (`2026-09-29`), which sorts and compares correctly on both
  engines.
- **DR-2.** JSON documents are stored as `TEXT`.
- **DR-3.** Money and prices are `REAL` (SQLite) / `DOUBLE PRECISION` (PostgreSQL).
- **DR-4.** Surrogate keys are `INTEGER PRIMARY KEY AUTOINCREMENT` (SQLite) /
  `BIGINT GENERATED BY DEFAULT AS IDENTITY` (PostgreSQL); inserts read the new id
  with `RETURNING id`.
- **DR-5.** `owner` is the workspace id from the session cookie. Every query on an
  owned table filters by it.
- **DR-6.** The two schema files MUST declare identical tables, columns and indexes
  (checked by `tests/test_portfolio.py`). There are no migrations. A database made
  before accounts belonged to the workspace (an `accounts.portfolio_id` column,
  `holdings.portfolio_id`, no `portfolio_accounts` or `portfolio_children`) must be
  rebuilt.

### 1.2 Tables

| Table | Key | Purpose |
|---|---|---|
| `plans` | `id` | One scenario: `owner`, `name`, `data` (the plan JSON, §2), `is_active` (0/1; one active per owner), `created_at`, `updated_at` |
| `portfolios` | `id` | `owner`, `name`, `currency` (base, default USD), `description`, `settings` (JSON: `targets` by asset class, and the last `projection` settings) |
| `securities` | `symbol` | Shared by every workspace. Descriptive fields (`name`, `quote_type`, `currency`, `exchange`, `asset_class`), latest quote (`last_price`, `prev_close`, `last_price_date`, `fetched_at`, `fetch_error`), long-run statistics (`lt_return`, `lt_vol`, `lt_years`, `lt_updated`), `dividend_yield`, `source` (`yahoo` or `manual`), `collect` (1: market data, collected daily whether held or not), `keep_days` (days of history kept; NULL: `prices.retention_days`), `notes` |
| `accounts` | `id` | One account of the workspace (not of a portfolio): `owner`, `name`, `type` (a key of `portfolio/account_types.TYPES`, which gives its kind - investments, cash, property, debt - and tax treatment), `owner_person` (0 you, 1 partner, −1 joint), `institution`, `currency` (of the values typed in; default the currency most of the workspace's accounts use), `value` (cash, property and debts), `as_of` (the date the value was set), `rate`, `payment` (monthly) and `term_months` (months left on `as_of`) for debts, `notes`, `created_at`, `updated_at` |
| `portfolio_accounts` | (`portfolio_id`, `account_id`) | Which accounts a portfolio includes directly, many-to-many (one account can be in any number of portfolios), with `position` (display order) |
| `portfolio_children` | (`parent_id`, `child_id`) | Portfolios made of other portfolios, with `position`: a parent includes every account of each child, recursively, each account counted once; the app refuses a cycle (a portfolio containing itself directly or through another) |
| `holdings` | `id` | A position in an investment account: `account_id`, `symbol`, `quantity`, `cost_basis` (total, nullable), `asset_class` (blank = use the security's), `notes`, `added_at` |
| `prices` | (`symbol`, `date`) | Daily bars: `open`, `high`, `low`, `close`, `adj_close`, `volume` (open, high, low and volume nullable); `WITHOUT ROWID` on SQLite |
| `fetch_runs` | `id` | One collection run: `reason` (schedule, startup, manual, new-symbol, admin), start/finish, counts of symbols, ok, failed, rows added and pruned, `message` |
| `projections` | `id` | A saved portfolio projection: `portfolio_id`, `created_at`, `settings`, `summary`, `result` (all JSON) |
| `import_drafts` | `id` | The portfolio builder's analysis of an upload: `owner`, `filename`, `created_at`, `data` (JSON) |
| `snapshots` | `id` | Net worth over time: `owner`, `taken_on` (date), `kind` (`all`: every account of the workspace, each once, `ref` blank; `portfolio`: one portfolio, `ref` = its id), `assets`, `liabilities`, `data` (JSON breakdown by kind: investments, cash, property, debt), `note`, `created_at`; one per owner, day, kind and ref, recorded after every price run or on request, kept for good |
| `app_settings` | `key` | Application-wide JSON values, e.g. the administrator's password hash |

Thirteen tables in all. Indexes: `plans(owner)`, `portfolios(owner)`, `accounts(owner)`,
`portfolio_accounts(account_id)`, `portfolio_children(child_id)`,
`holdings(account_id)`, `holdings(symbol)`, `prices(date)`, `projections(portfolio_id)`,
`import_drafts(owner)`, unique `snapshots(owner, taken_on, kind, ref)`.

### 1.3 Relationships

```
owner ─┬─< plans
       ├─< accounts ─< holdings >── securities ─< prices
       │     ^
       │     │ portfolio_accounts (many-to-many)
       │     │
       ├─< portfolios ─┬─< projections
       │     ^         └─< portfolio_children >── portfolios (nested)
       ├─< import_drafts
       └─< snapshots
fetch_runs, app_settings: global
```

- Accounts belong to the workspace (`owner`). Deleting a portfolio never deletes
  an account; deleting an account takes it out of every portfolio.
- `portfolio_accounts.portfolio_id` → `portfolios.id` and
  `portfolio_accounts.account_id` → `accounts.id`, both **ON DELETE CASCADE**.
- `portfolio_children.parent_id` and `.child_id` → `portfolios.id`, both **ON
  DELETE CASCADE**. A portfolio's accounts are its own `portfolio_accounts` plus,
  recursively, those of its children, each counted once.
- `holdings.account_id` → `accounts.id` **ON DELETE CASCADE** (NOT NULL; only
  investment accounts hold positions).
- `holdings.symbol` → `securities.symbol` (no cascade: a held security cannot be
  deleted).
- `prices.symbol` → `securities.symbol` **ON DELETE CASCADE**.
- `projections.portfolio_id` → `portfolios.id` **ON DELETE CASCADE**.
- Cash inside an investment account is the reserved symbol `CASH`, priced at 1 in
  the account's currency. Values are converted daily from each account's currency
  into the portfolio's currency. A cash account has no holdings: its `value` counts as cash in
  the investable assets.
- A debt's `value` is what was owed on `as_of`; it is paid down month by month from
  then, with `payment`, or the level payment from `rate` and `term_months` when there
  is none.
- An FX rate is an ordinary security `<FROM><TO>=X` with its own prices.

### 1.4 Retention rules

- **DR-7.** `prices` keeps `prices.retention_days` (365) of bars - or a security's own
  `keep_days` when it is set (market data: 2 to 20 years); older rows are deleted
  after every collection run. Monthly history is never stored — only the
  three `lt_*` numbers.
- **DR-8.** `projections` keeps the 10 most recent runs per portfolio.
- **DR-9.** `import_drafts` older than seven days are deleted when a new draft is
  saved.
- **DR-10.** Simulation results for plans are not persisted; they are held in memory
  per plan id and dropped whenever that plan is saved.

### 1.5 Legacy plan files

On first use of a workspace with no rows in `plans`, a file
`<data_dir>/plans/<workspace>.json` is imported once if present; otherwise the
sample household is created.

## 2. The plan (`retplan/plan.py`)

`plan_from_dict` builds a `Plan` from JSON, ignoring unknown keys and defaulting
missing ones; `to_dict` is its inverse. Rates are fractions (0.04 = 4%); ages are
years; money is in the plan's single, unnamed currency.

### 2.1 `Plan`

| Field | Meaning |
|---|---|
| `label`, `horizon` | Name; number of annual periods after period 0 (up to 80) |
| `portfolio_id` | The portfolio the plan is linked to (0 = none): the portfolio's accounts and debts are brought in line with it every time the plan is read (`web/plan_link.py`) |
| `persons` | list of `Person` |
| `income`, `expenses`, `loans` | lists of `IncomeRow`, `ExpenseRow`, `Loan` |
| `wrappers`, `ledgers` | lists of `Wrapper` and `Ledger` (accounts) |
| `conversions` | list of `Conversion` (§2.3) |
| `market` | `MarketSpec` (§2.4) |
| `tax` | `TaxSystem` (§2.5) |
| `policy` | `Policy` |
| `smile` | `SmileCurve`: ages and multipliers, linearly interpolated |
| `platform_fee`, `adviser_fee` | Annual fees on every account, on top of fund costs |
| `timing` | begin / mid / end — stored and editable; the engine applies flows before returns regardless |
| `seed` | Seed for every random stream |

### 2.2 Household and flows

| Class | Fields |
|---|---|
| `Person` | `label`, `age` (at plan start), `retire_age`, `death_age` (planning age), `included` |
| `IncomeRow` | `label`, `owner` (person index), `category`, `amount`, `basis` (real / nominal), `growth`, `grow_from_start`, `start_age`, `end_age` (owner's ages), `taxable_fraction`, `survivor_fraction` (share continuing after the owner's planning age), `probability` (expected-value scaling), `enabled` |
| `ExpenseRow` | `label`, `amount`, `basis`, `essential`, `infl_delta` (growth above CPI), `smile`, `start_age`, `end_age`, `owner` (−1 = household, ages of person 0), `recur_years` (0 = yearly; *n* = every *n* years from the first live year), `probability`, `enabled` |
| `Loan` | `label`, `balance`, `rate` (nominal), `term_years`, `kind` (amortising / interest_only / bullet), `extra_payment` (nominal, per year), `start_year`, `enabled`, `account_id` (the portfolio debt it mirrors; 0 = the plan's own) |

Income categories: `employment`, `self_employment` (both "earnings": they are the
pay base for %-of-earnings contributions and match), `rental`, `db_pension`,
`state_pension`, `annuity`, `other_taxable`, `tax_free`, `one_off`.

### 2.3 Wrappers and accounts

| Class | Fields used by the engine |
|---|---|
| `Wrapper` | `withdrawal_taxable_fraction`, `realises_capital_gains` (withdrawals taxed on their gain share), `cap_type` (none / absolute / pct_income) and `cap_value`, `catch_up_age`, `catch_up_amount`, `early_age`, `early_penalty`, `mrd_age`, `mrd_divisors` ([age, divisor] pairs), `lock_age`, `liquid` |
| `Ledger` | `wrapper` (index), `owner`, `opening`, `basis`, `weights` (one per asset class), `glide_to`, `glide_start_age`, `glide_end_age`, `withdraw_priority`, `contribute_priority`, `contribution` (real, per year), `contribution_pct_income`, `employer_match_pct`, `employer_match_cap_pct`, `rebalance` (annual / none), `enabled`, `account_id` (the portfolio account it mirrors; 0 = the plan's own) |
| `Conversion` | `label`, `from_ledger`, `to_ledger`, `mode` (amount / fill_to), `amount` (real a year, or the taxable-income target), `start_age`, `end_age` (person 1's age; end exclusive), `enabled` |

`Wrapper` also carries `contribution_deductible`, `growth_taxed_annually`,
`growth_taxable_fraction` and `tax_free_lump_sum`. They are stored and shown but
not used by the engine (a tax-free lump sum is expressed through
`withdrawal_taxable_fraction`).

### 2.4 Markets (`retplan/markets.py`)

| Class | Fields |
|---|---|
| `AssetClass` | `label`, `mu` (arithmetic expected simple return), `sigma`, `income_yield` (informational), `ter`, `crash_beta` |
| `Regime` | `label`, `mean_offset`, `vol_mult`, `corr_tighten`, `trans` (row of the transition matrix) |
| `CrashSpec` | `enabled`, `prob`, `depth_min` / `depth_mode` / `depth_max`, `duration`, `shape`, `recovery_fraction`, `recovery_periods` |
| `InflationSpec` | `mode` (fixed / path / stochastic), `mean`, `sd`, `persistence`, `corr_equity`, `path` |
| `MarketSpec` | `mode` (fixed / path / mc / historical), `dist` (lognormal / normal / t), `nu`, `assets`, `corr`, `regimes`, `start_regime`, `crash`, `inflation`, `fixed_path`, `historical`, `block_length`, `fixed_basis` (typical / average), `antithetic`, `calibrate` |

### 2.5 Tax (`retplan/tax.py`)

| Class | Fields |
|---|---|
| `Schedule` | `lowers` (band lower bounds, first = 0, strictly ascending), `rates` (in [0, 1]), `allowance`, `taper_start`, `taper_rate`, `cap` |
| `TaxSystem` | `ordinary` (the schedule every taxable amount uses), `capital` (stored, unused), `surtax_rate`, `surtax_threshold`, `cg_inclusion`, `index_bands` |

### 2.6 Policy

`method` (fixed_real / fixed_nominal / pct_portfolio / vpw / guardrails / table),
`pct`, `vpw_rate`, `guard_up`, `guard_down`, `guard_cut`, `guard_raise`,
`guard_final_years`, `inflation_skip`, `legacy_target` (real), `sweep_ledger`,
`confidence`, `discount_rate`. `cash_buffer_years` is stored but not used by the
engine.

## 3. Engine results (`retplan/engine.Results`)

Arrays of shape (trials, T+1), all in real terms: `balance` (start of period),
`balance_close`, `balance_by_wrapper` (trials, T+1, wrappers), `income` (including
forced distributions), `mrd`, `spend` (including debt service), `tax`,
`withdrawal`, `contribution` (including `employer`), `conversion`, `fees`, `ret_rate`,
`shortfall`, `taxable_income`, `debt_balance`, `net_worth`; plus `cpi`, `regime`
and `ages` (person 0).

## 4. Order of operations within period `t`

1. Record opening balances (total and by wrapper).
2. Income: real rows plus nominal rows deflated by this trial's CPI.
3. Minimum distributions from every wrapper past its MRD age (balance ÷ divisor),
   added to income and to taxable income.
4. Conversions: move money between accounts (not in the final period); the source
   wrapper's taxable share joins taxable income.
5. Spending target from the policy; debt service deflated by CPI.
6. Allowance (tapered by income alone), tax on income, surtax.
7. Need = spending + debt + tax on income − income. Withdraw in withdrawal priority,
   each grossed up exactly for tax and penalty; the unmet remainder is shortfall.
8. Surplus = income − spending − debt − tax, if positive, funds contributions in
   contribution priority (not once the whole household is retired, and not in the
   final period), then employer match, then the sweep account.
9. If not the final period: charge fund, platform and adviser fees, apply real
   returns per asset, rebalance to next period's weights where `rebalance = annual`.
10. Record the period's implied portfolio return; update the guardrail multiplier.

- **DR-11.** Reconciliation identity, per period and trial:
  `balance[t+1] = (balance[t] − withdrawal − mrd + contribution − fees) × (1 + ret_rate)`.

## 5. Portfolio projection data (`portfolio/projection.py`)

| Class | Fields |
|---|---|
| `CashFlow` | `kind` (contribution / withdrawal), `amount` (per year), `start_year`, `end_year` (1 = first projected year), `indexed`, `growth`, `label` |
| `Settings` | `years`, `frequency` (annual / quarterly), `trials`, `method` (parametric / fat_tails / bootstrap), `return_source` (blend / assumption / history), `inflation`, `fee`, `rebalance` (annual / quarterly / none), `target`, `withdrawal_rate`, `flows`, `stress` (scenario key), `overrides` ({symbol: {mu, sigma}}), `seed` |
| `AssetInput` | One per symbol (a symbol in two accounts is one asset): value in base currency, daily adjusted closes in base currency, `lt_return`, `lt_vol`, `lt_years` |
| `AssetModel` | The estimate per asset: weight, `mu`, `sigma`, days used, notes on where each came from, one-year volatility |

A result is plain JSON — `settings`, `summary`, `periods`, `expected`,
`representative`, `assets`, `corr`, `hist_end`, `hist_dd`, `notes`, `stress`,
`run_date` — which is what `projections.result` stores and what the page draws
from.
