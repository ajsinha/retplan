The usual symptoms, the usual cause of each, and what to do. Start with the audit: a surprising number of “wrong” answers are an input the audit has already flagged. {{ goto('audit', 'Open the audit') }}

My edit does not show up

  • It was not saved. A dialog saves when you press Add to my plan or Save changes; closing it discards the answers. In the table view and on the other editor pages, leaving without pressing Save changes discards the edit without a warning, and rows marked for deletion go only when you save.
  • It is paused. A faded card marked paused is kept but left out of the plan; Include again in its menu brings it back.
  • The simulation results vanished. That is deliberate: saving a change throws away that plan’s simulation results, because they described the old plan. The dashboard falls back to the fixed-return view until you press Run simulation again.
  • You edited a different scenario. The editor, dashboard and reports all show the active scenario, named in the top bar. Switch to the one you meant. {{ goto('scenarios', 'Open scenarios') }}
  • The change has no effect by design. A later retirement age does little if the salary row still ends at the old age; its “To age” is separate. Likewise a planning age beyond the horizon changes nothing until the horizon is raised.

The numbers look wrong

  • A blocking audit check is failing. The dashboard shows a red banner. Fix that first.
  • Net instead of gross income. Income is entered before tax; entering take-home pay makes the model tax it again.
  • Nominal instead of real. A nominal row with 3% growth is roughly flat in real terms, and a nominal pension shrinks every year.
  • The deterministic view looks too rosy. It grows every asset at its arithmetic average; the simulated median is the more honest number.
  • Maximum spend is lower than first-year spending. The solver figure excludes debt payments; the tile includes them.

Different numbers from run to run

Nothing is random between identical runs: the same plan, seed and trial count always give the same answer. If a number moved, one of these changed:

  • the trial count — more trials add futures, so the estimate moves within its error bar;
  • the seed on the household page;
  • the plan itself, including a scenario switch;
  • the page: the compare page uses 1,500 trials on a fixed seed, and the solvers use half your trial count capped at 1,500, so their success figures differ slightly from the dashboard headline.

See {{ goto('help_simulation', 'Running a simulation') }}.

A run fails or the dashboard shows an error

  • Regime transition rows must sum to 1. A regime row that is out by even a hundredth of a point stops the market engine, and with it the dashboard, the reports and the audit. Make each row exactly 100%. {{ goto('plan_section', 'Open markets', 'markets') }}
  • Historical mode needs at least 2 rows of data. Add history or switch the market mode back to mc.
  • Very long runs. A full analysis at 25,000 trials runs the model many times; allow a few minutes, or use fewer trials.

Portfolio prices

  • A holding shows as unpriced. Yahoo does not know the symbol as typed. Check the exchange suffix (VOD.L, not VOD) and use the symbol search. Until it prices, the holding counts as zero in every total.
  • Prices are stale. Collection runs once a day at the configured time (18:30 local by default) and at start-up if the last run is old. If [prices] enabled is false, or RETPLAN_PRICES_ENABLED turns it off, nothing is collected; the prices page can also run a collection on demand.
  • “request failed: HTTP Error 429”. Yahoo is throttling. The collector already backs off and retries twice; wait an hour and run again.

More in {{ goto('help_prices', 'Daily prices') }}.

My plans have disappeared

Your browser finds your workspace through an opaque id in its session cookie. Clear cookies, switch browser or use a private window, and you arrive in a new, empty workspace. The old plans are still in the database, but this browser no longer has the key to them. The same happens to everyone if the session secret changes (a new RETPLAN_SECRET, or the .session-secret file in the data folder deleted).

The server will not start: database schema error

RetPlan creates its tables from schema/sqlite.sql or schema/postgres.sql when the database is empty, but it never migrates. If the database has some RetPlan tables but not all, start-up stops with a message naming the missing tables. Either create them from the schema file, or point the configuration at a fresh database (and copy the data across with tools/copy_db.py). See {{ goto('help_system', 'System and database') }}.
