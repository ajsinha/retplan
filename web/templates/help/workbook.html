RetPlan began as a spreadsheet, and the spreadsheet still ships: RetPlan.ods in the project folder, a LibreOffice Calc workbook with the whole deterministic model written as visible formulas. The two were built to agree exactly; since this release the web application is developed on its own and the workbook is kept as it was, so their numbers now differ in the ways listed below.

What is in the workbook

  • 24 worksheets: guided input sheets, a fully visible formula engine, simulation sheets, a dashboard with ten charts, three reports and an audit sheet.
  • Live formulas for the whole fixed-return projection — income, tax, withdrawals, balances. They need no macros and work with macros blocked.
  • Buttons on the dashboard that run the Monte Carlo and the solvers. These call Python macros and need a little setup (below).

How the application now differs

Up to version 1.0 a cross-check compared the workbook’s formulas with the Python engine column by column and found them equal to about 7×10−12. The application has since corrected five things the workbook still does the old way:

  • Employer matches are new money paid on top of your saving, not taken out of the household’s surplus.
  • The funded ratio no longer counts forced withdrawals from your own accounts as outside income (they were counted twice).
  • The fixed-return projection compounds at each asset’s typical (median) rate by default rather than its arithmetic average.
  • The earliest-retirement solver extends salaries when it tries a later retirement age, and the sensitivity drivers for fees and longevity behave sensibly.
  • The sample household’s cash reserve and rental property are invested in the right asset classes.

So for the same inputs, expect the workbook to show a higher funded ratio, a more optimistic fixed-return path, and less saved where there is an employer match. make verify will report these differences; that is expected.

When to use which

Use the web app when…Use the workbook when…
you want to enter a plan quickly, keep several scenarios and compare them you want to see and audit every intermediate number as a formula
you want your actual holdings priced daily and projected you want to work offline in a file you can email or archive
you want the help, the wizard and the charts with tables you want to change the model itself and see the effect cell by cell

Plans do not move between the two automatically: the web app imports and exports its own JSON, not .ods files.

Setting it up

From the project folder, with LibreOffice closed:

  • make build — generates RetPlan.ods from source through LibreOffice (about a minute and a half).
  • make setup — installs the macros into your LibreOffice profile and trusts this folder, so the buttons are allowed to run.
  • Open RetPlan.ods, work through Start Here, and press Run simulation on its dashboard.

    The tools

    CommandWhat it does
    make testUnit, engine and statistical tests. No LibreOffice needed; a few seconds.
    make buildBuilds the workbook from source.
    make verifyRuns tools/crosscheck.py: proves the workbook’s formulas and the engine agree to 1e-9.
    make simulateRuns tools/simulate.py: the Monte Carlo and solvers from outside LibreOffice, results written into the workbook (it saves in place).
    make installRuns tools/install_macros.py: copies (never links) the macro module and the engine into your LibreOffice profile, so what runs is what you can read.
    make trust / make untrustRuns tools/trust_folder.py: adds or removes this folder in LibreOffice’s trusted locations. --list shows the current ones.
    make checkThe full gate: test, build, verify, simulate.
    make webStarts this web application on port 5007.
    {% call note('tip', 'No macro setup at all') %}

    If you would rather not touch LibreOffice’s security settings, python3 tools/simulate.py RetPlan.ods --trials 10000 --full runs exactly the code the buttons run and needs only python3-uno.

    {% endcall %}

    Known differences

    • The sheet assumes annual rebalancing; the engine also honours “none”.
    • The workbook is built at fixed sizes: 100 income and spending rows, 10 loans, 6 accounts, 6 wrappers, 6 asset classes and a 60-year horizon.
    • Workbook scenarios store scalar assumptions only, not whole tables. Web scenarios are complete copies of the plan.
    • Only LibreOffice is supported; an Excel version is not built.
