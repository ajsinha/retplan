Every symbol held in any portfolio is priced once a day from Yahoo Finance. The prices page shows what is tracked, how many daily closes are kept for each, the long-run statistics, and a log of every collection run.

Where prices come from

RetPlan talks directly to two public Yahoo Finance endpoints: one returns daily or monthly bars with adjusted closes (restated for dividends and splits, so a return computed from them is a total return), the other powers the symbol search when you add a holding. No API key is needed.

{% call note('warn', 'An unofficial source') %}

These endpoints are not a supported product. Yahoo can change or throttle them without notice. RetPlan is defensive about it — a failure for one symbol is recorded against that symbol and never stops the rest of the run, requests are retried, and a "too many requests" answer is backed off from — but a price is only as reliable as its source. It is a planning tool, not a trading feed.

{% endcall %}

When prices are collected

  • Daily, on a schedule. While RetPlan is running, a background thread collects every tracked symbol at run_at local time (18:30 by default, after the US close).
  • At start-up, if stale. If the last successful run began more than 20 hours ago — a laptop asleep at 18:30, a server restarted — a catch-up run starts about five seconds after RetPlan does.
  • When you add a symbol. A symbol added on its own is priced immediately; a pasted list is priced in the background.
  • On request. Refresh prices on a portfolio (at once for up to eight symbols, in the background for more), or Collect now on the prices page for everything.
  • From cron, if RetPlan is not always running. See below.

Only one collection runs at a time; a second request waits for the first rather than fetching twice. There is a short pause between symbols to be polite to the endpoint, so a large list takes a little while.

What a run fetches

A symbol seen for the first time gets a year of daily closes. After that, each run asks only for the smallest range that covers the gap since the last stored close — five days, one, three or six months, or a year — and overwrites the overlap, because adjusted closes change after every dividend. Exchange-rate pairs needed by any portfolio are collected in the same run, including a pair discovered during the run itself when a new symbol turns out to be quoted in a new currency.

Why only a year is kept

After each run, daily closes older than the retention window (retention_days, 365 by default) are deleted. A year of daily data is what the projection needs for recent volatility, correlations and the bootstrap, and keeping it bounded keeps the database small no matter how long RetPlan runs.

Long-run behaviour comes from somewhere else: about once every 30 days, each security's 20 years of monthly prices are fetched, reduced to three numbers — annualised return, annualised volatility, and the number of years of history — and the monthly prices are thrown away. Those three numbers are what the prices and security pages show as long run, and what the projection uses to calibrate. At least 25 months of history are needed; exchange rates get no long-run statistics.

{% call note('why', 'Why not keep twenty years of daily prices?') %}

They would not improve the projection. Its expected returns come mainly from long-run class assumptions (see where assumptions come from), and the only use for long history is a return and a volatility — which the three stored numbers already are.

{% endcall %}

Collecting from cron instead

If RetPlan is not running all day, let the operating system do the collecting. From the project directory:

python tools/fetch_prices.py                 # every held symbol, once
python tools/fetch_prices.py VTI BND         # just these symbols
python tools/fetch_prices.py --prune-only    # only delete closes past retention

# crontab: weekdays at 18:30
30 18 * * 1-5  cd /path/to/retplan && .venv/bin/python tools/fetch_prices.py

It uses the same database as the web application (from the configuration file or RETPLAN_DATABASE_URL), runs the same collector, records the run in the same log (reason cli), prunes old closes and exits — non-zero if every symbol failed. Running it alongside the built-in schedule is harmless.

Reading the prices page

  • Schedule: the daily time and the next run, or off.
  • Symbols tracked: every held symbol plus the exchange-rate pairs portfolios need.
  • Securities: the last close and its date, closes kept, the long-run return and volatility, how many portfolios hold it, and a status: ok, pending (never priced yet) or error with Yahoo's reason.
  • Collection runs: why each run happened (schedule, startup, manual, new-symbol, fx, cli), how many symbols succeeded and failed, rows written and pruned, and any errors.

Click a symbol for its own page: a year of daily closes, the past year's total return, annualised volatility, worst fall, the long-run figures, its asset class (which you can change there), and which of your portfolios hold it.

Looking up and managing securities

{{ goto('securities', 'Securities') }} looks up any symbol or name on Yahoo - a year of prices, volatility, the worst fall, long-run return and dividend yield - without storing anything. Everyone can do that.

Changing the securities list itself is for an administrator, because securities and prices are shared by every workspace on the server:

  • Add a security, priced either from Yahoo daily, or manually - for a private fund, a property or anything Yahoo does not cover. A manual security's closes are typed or pasted in (date, close[, adjusted close], one per line) and the daily collector never touches it.
  • Amend its name, currency, type, exchange, notes, price source, and the asset class every workspace's holdings follow by default.
  • Add or delete individual closes. The latest stored close becomes the security's price. Typed prices on a Yahoo security are overwritten by the next collection.
  • Delete the security and all its prices - refused while any holding, in any workspace, still holds it.

Who is an administrator is set in config/retplan.toml under [admin]. With no password (the default), anyone using the app on the computer it runs on is an administrator, which suits a personal install. Set a password to administer from elsewhere; you then sign in at /admin/login. Behind a reverse proxy always set one, because every proxied request looks as if it came from the same computer.

{% call note('warn', 'Manual prices and the retention window') %}

Typed closes older than the retention window (365 days by default) are not stored, and are pruned like any others. A quarterly valuation is fine for the portfolio's value; a projection estimates a holding's own volatility only from at least 60 closes and otherwise uses its asset class's assumption.

{% endcall %}

When a symbol will not price

Almost always the symbol is not the one Yahoo uses. Search for the name when adding the holding and pick from the list rather than typing a ticker from memory. Yahoo's conventions:

USthe plain tickerVTI, AAPL, BRK-B (a dash, not a dot)
London.L suffixVOD.L, VWRL.L
Toronto.TO suffixSHOP.TO
Australia.AX suffixVAS.AX
Germany (Xetra).DE suffixSAP.DE
Crypto-USD (or another currency)BTC-USD, ETH-USD
Indices^ prefix^GSPC — an index is not something you can hold; add the fund that tracks it
